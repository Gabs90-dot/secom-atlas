# \# ATLAS - Product Vision

# 

# \## Missione

# 

# ATLAS deve diventare il miglior CRM tecnico operativo per aziende di assistenza, manutenzione e gestione impianti.

# 

# Non deve essere un clone di GLPI.

# 

# Deve essere uno strumento più pratico, più veloce e più utile per chi lavora realmente su ticket, clienti, sedi, contratti, tecnici, materiali e interventi.

# 

# \## Target

# 

# ATLAS è pensato per aziende che gestiscono:

# 

# \* assistenza tecnica

# \* manutenzione programmata

# \* manutenzione straordinaria

# \* impianti tecnologici

# \* videosorveglianza

# \* biometria

# \* sistemi SPIS/SPISPHOTO

# \* apparati hardware/software

# \* clienti pubblici e privati

# \* squadre tecniche sul territorio

# 

# \## Differenza rispetto a GLPI

# 

# GLPI è principalmente un sistema ITSM/ticketing.

# 

# ATLAS deve essere:

# 

# \* più operativo

# \* più mobile

# \* più vicino al tecnico

# \* più vicino al cliente

# \* più integrato con contratti e bolle

# \* più utile per il commerciale

# \* più utile per il responsabile operativo

# \* più leggibile per la direzione

# 

# \## Moduli centrali

# 

# \* Clienti

# \* Sedi

# \* Ticket

# \* Registro interventi

# \* GLPI Sync

# \* Contratti

# \* Bolle di lavoro

# \* Asset

# \* Magazzino

# \* Tecnici

# \* Calendario

# \* Portale clienti

# \* Dashboard operative

# \* KPI direzionali

# 

# \## Principio guida

# 

# Ogni funzione deve rispondere a una domanda pratica:

# 

# "Questa cosa aiuta davvero Secom a lavorare meglio?"

# 

# Se la risposta è no, non va sviluppata.

# 

# \## Obiettivo finale

# 

# ATLAS deve permettere di:

# 

# \* aprire ticket velocemente

# \* assegnare tecnici

# \* vedere storico cliente

# \* sapere contratto attivo

# \* generare bolla

# \* registrare materiali

# \* sincronizzare GLPI

# \* controllare carichi di lavoro

# \* produrre dati utili alla direzione

# \* dare al cliente un portale consultabile
